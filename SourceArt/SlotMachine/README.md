# Lucky Star — 1960s mechanical slot machine

Original teal enamel, chrome and brass cabinet with three independent reels, a side-mounted ruby-red ball lever, printed marquee/paytable, coin entry and payout tray.

## Files

- `Lucky_Star_1960s.blend`: editable Blender 5.0 source, five rigid mesh objects, packed textures, rig, animation and studio camera.
- `exports/SK_SlotMachine.fbx`: skinned model and baked 30 fps animation, in real-world scale. Import as a skeletal mesh with animations.
- `textures/T_SlotMachine_BaseColor.png`: 4096 × 4096 UV-baked base color.
- `textures/T_SlotMachine_ORM.png`: 4096 × 4096 UV-baked material properties; R = neutral occlusion (1), G = roughness, B = metallic. Import as linear/non-sRGB masks.
- `previews/SlotMachine_Jackpot.png` and `SlotMachine_LeverPulled.png`: actual Blender renders.
- `previews/UV_Layout.svg`: exact final UV cage.
- `asset_audit.json`: topology and export measurements.
- `animation_samples.json`: sampled bone rotations from the saved Blender scene.

## Topology and UVs

The five source mesh objects contain 18,537 quads and 18,700 vertices. There are no triangles or n-gons. `Cabinet`, `Lever`, `Reel_1`, `Reel_2` and `Reel_3` are separate editable objects. All moving parts have rigid, one-bone vertex weights. Cylinders have quad-grid caps; the ball uses a quad sphere. The three printed plaque faces are intentional open quad surfaces. All solid shells are closed.

The non-overlapping atlas is `BakeUV`, exported as UV channel 0. Source artwork is baked into this atlas; the final material does not depend on generated coordinates or triplanar mapping. Unreal triangulates the render mesh as required by its renderer; the editable Blender source retains quads.

## Animation

`A_Pull_Spin_Jackpot_12s`, frames 1–361 at 30 fps:

- 0–0.5 s: ready.
- 0.5–1.2 s: lever pulls forward 64°.
- 1.1 s: the reels start spinning independently.
- 1.4–2.2 s: lever returns upright.
- 4.9 / 5.55 / 6.2 s: reels stop one at a time on 7–7–7.
- 6.2–12 s: the jackpot remains visible before the next pull.

The loop is baked into the exported animation and uses complete reel revolutions, so the endpoint matches the starting pose.

## Unreal

Assets are installed under `/Game/SlotMachine`. `BP_LuckyStarSlotMachine` is a reusable Blueprint derived from SkeletalMeshActor. Its component uses the imported animation, with Playing and Looping enabled in serialized Animation Data. This starts automatically in Play/Simulate without an editor Python dependency at runtime. The placed actor also updates animation in a realtime editor viewport.

The existing `/Game/ThirdPerson/Lvl_ThirdPerson` level contains the machine and a dedicated showcase camera. The Blueprint's Animation → Play Rate controls the entire cycle: a value of `12 / X` repeats every X seconds, scaling both movement and hold times. For independently changing only the jackpot pause, extend or shorten the hold at the end of the Blender action and re-export.

Press Play in the existing level: `LS_SlotMachine_Showcase` automatically switches to the saved camera and loops. The machine's Blueprint plays the imported skeletal animation independently. The baked material is two-sided so the three printed quad plates display in Unreal. Native engine screenshots in `previews/Unreal_LeverPulled.png` and `previews/Unreal_Jackpot.png` show the running result. `runtime_samples.json` records actual component playback and bone rotations across two automatic restarts.

## Blender workflow

Open the blend file and use the named workspaces: **01 Showcase**, **02 Quad Topology**, **03 UV Atlas**, and **04 Animation**. The scene opens at the jackpot pose. Space plays the 12-second animation. The modeling workspace enables wire edges; select the meshes and enter Edit Mode to inspect the quad loops. The UV workspace has the baked atlas loaded; select the meshes and enter Edit Mode to see the UV islands. Timeline markers identify the pull, individual reel stops, and jackpot. The README and generator scripts are also embedded as Blender text blocks.

Rebuild source with Blender's `--background --python build_slot_machine.py`, then run `finalize_blender.py` to pack the source and export QA evidence. The Unreal importer is `EnvProd3_271/Content/Python/import_slot_machine.py` (run inside the full Unreal Editor; its import UI services are not available in a commandlet).

## Artwork provenance

The marquee was generated with the built-in ImageGen tool and copied into `textures/Marquee_Generated.png`. The exact generation prompt is in `image_prompt.txt`. Reel symbols and paytable typography are original deterministic artwork generated by `make_graphics.py`. Final game textures are baked by Blender from those sources and the physical material colors/properties.
